# Athlete OS — Data model — v2

Postgres via Drizzle. Conventions:

- `snake_case` tables/columns, `uuid` primary keys. **Client-generated ids are allowed** for `workouts`, `workout_exercises`,
  `strength_sets` (offline-first); the server upserts by `(id, user_id)`.
- `timestamptz` for instants; **day columns are computed at write time** from the source's own local time (activities) or the
  athlete's timezone (declared data). Never derive a calendar day from a timestamp at read time.
- JSONB validated by Zod at every boundary; evolving taxonomies (`stimulus_key`, `kind`, `type`, `metric`) are `text` + Zod, not
  Postgres enums (drizzle-kit cannot rename enum values safely).
- Every user-owned table has `user_id`, `created_at`, `updated_at` and **`.enableRLS()` with no policies** (deny-all for the
  Supabase Data API). The app reaches Postgres through a least-privilege role with Drizzle; ownership is enforced in code by the
  `scoped(db, userId)` repository (see ARCHITECTURE §7).
- Every derived or imported row has a natural key and is written with `ON CONFLICT DO UPDATE` (`UNIQUE NULLS NOT DISTINCT`).

## 3. Unified workouts

## 12. JSONB contracts (Zod, in `src/domain`)

`NormalizedWod`, `WodAnalysis` (`domain/wod`), `CardioStep[]` (`domain/cardio`), `Recommendation` (`domain/engine/types.ts`),
`StrengthPrescription` (`domain/strength/types.ts`), `ReadinessSummary` (`domain/readiness`), `HrZoneSet` (`domain/cardio/zones.ts`).
Every JSONB write goes through `schema.parse()`; every read through `schema.safeParse()` with a logged fallback.
